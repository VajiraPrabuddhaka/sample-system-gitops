# OpenChoreo with Flux

This directory contains everything you need to install OpenChoreo with Flux. The `../argocd` directory has the same setup for Argo CD.

## Plug In the Repository

Run the following steps from the root of the repository:

1. Install Flux **2.5 or later** by following its [installation guide](https://fluxcd.io/flux/installation/). You can use `flux install`, `flux bootstrap ...` or the Flux Operator.

2. Apply `plug.yaml`, or commit it to the repository your Flux already syncs:

   ```bash
   kubectl apply -f flux/clusters/k3d-single/plug.yaml
   ```

   This creates the GitRepository `openchoreo` (pointing to this repository) and the Kustomization `openchoreo`, which syncs `clusters/k3d-single`.

3. Watch the Kustomizations:

   ```bash
   kubectl -n flux-system get kustomizations -w
   ```

   Each `openchoreo-*-registration` Kustomization becomes Ready once that plane's agent has connected. `openchoreo-platform-defaults` is the last one to become Ready.

### One Cluster per Plane (k3d-multi)

To run each plane in its own cluster (`clusters/k3d-multi`), install Flux on each of the four clusters and apply that cluster's `clusters/k3d-multi/<plane>/plug.yaml` using its context. Refer to the [multi-cluster section](../README.md#multi-cluster-setup-on-k3d-k3d-multi) of the top-level README for more details.

### Forks, Release Tags & Private Repositories

- **Forked or mirrored repository** - Run `scripts/set-git-source.sh <url> [branch]`. It rewrites `plug.yaml` to point at your repository.
- **Tracking a release tag** - To track a release tag instead of a branch, change `ref.branch` to `ref.tag` in `plug.yaml`.
- **Private repository** - Add a `secretRef` to the GitRepository. There is a commented example in `plug.yaml`.

## Conventions

- **Unit** - A directory under `shared/`, `identity/` or `planes/`, which maps to one Flux Kustomization defined by the cluster in `clusters/<name>/units.yaml`. A unit's `kustomization.yaml` pulls in `release.yaml` (chart source + HelmRelease, in `flux-system`), `manifests/`, and a hash-suffixed ConfigMap `<component>-values-base` generated from `values.yaml`.
- **Per-cluster values** - The ConfigMap `<component>-values`, generated by `clusters/<name>/kustomization.yaml` from `values/<component>.yaml`. Every HelmRelease reads it as an optional second `valuesFrom`.
- **Order** - Defined with `dependsOn` in `units.yaml`. The defaults shared by all units (source, interval, prune, wait) are a single patch in the cluster's `kustomization.yaml`.
- **Registration details** - The data plane host and port and the observer URL are `spec.patches` on the registration units in `units.yaml`.

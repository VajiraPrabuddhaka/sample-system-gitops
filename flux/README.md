# OpenChoreo with Flux

Everything here is for Flux. `../argocd` is the same thing for Argo CD.

## Plug in

1. Install Flux **2.5 or later** from its own guide: https://fluxcd.io/flux/installation/
   (`flux install`, `flux bootstrap ...` or using the Flux Operator).
2. Apply `clusters/k3d-single/plug.yaml`, or commit it to the repo your Flux syncs. It
   creates GitRepository `openchoreo` (this repo) and Kustomization `openchoreo`, which
   syncs `clusters/k3d-single`.
3. Watch: `kubectl -n flux-system get kustomizations -w`. `openchoreo-*-registration` turn
   Ready when that plane's agent has connected; `openchoreo-platform-defaults` is last.

One cluster per plane (`clusters/k3d-multi`): install Flux on each of the four clusters
and apply that cluster's `clusters/k3d-multi/<plane>/plug.yaml` with its context (see
the k3d-multi section of the top-level README).

Forked or mirrored? `scripts/set-git-source.sh <url> [branch]` rewrites `plug.yaml`.
To track a release tag instead of a branch, change `ref.branch` to `ref.tag` in `plug.yaml`.
Private repo: add a `secretRef` to the GitRepository (commented in `plug.yaml`).

## Conventions

- **Unit** = a directory under `shared/`, `identity/` or `planes/` = one Flux Kustomization,
  defined by the cluster in `clusters/<name>/units.yaml`. A unit's `kustomization.yaml`
  pulls in `release.yaml` (chart source + HelmRelease, in `flux-system`), `manifests/`, and
  a hash-suffixed ConfigMap `<component>-values-base` made from `values.yaml`.
- **Per-cluster values**: ConfigMap `<component>-values`, generated by
  `clusters/<name>/kustomization.yaml` from `values/<component>.yaml`. Every HelmRelease reads
  it as an optional second `valuesFrom`.
- **Order**: `dependsOn` in `units.yaml`. Shared defaults for all units (source, interval,
  prune, wait) are a single patch in the cluster's `kustomization.yaml`.
- **Registration details** (data plane host/port, observer URL) are `spec.patches` on the
  registration units in `units.yaml`.
